# FRIDAY Runbook

Operational playbook for FRIDAY (your agency's AI Technical Director). FRIDAY is a Next.js/TypeScript
app meant to run 24/7 under a process supervisor of your choice (systemd, launchd, pm2, …), serving on
`http://127.0.0.1:3737`. Her datastore is a **local JSON file store** at `~/.agentic-os/friday` (one file per
collection: `clients.json`, `projects.json`, `tasks.json`, `approvals.json`, `requests.json`,
`runs.json`, `messages.jsonl`, `logs.jsonl`, `schedules.json`, `escalations.json`, …). There is **no SQL
database**.

`[Owner: …]` marks bracketed items only the owner can fill in or must do by hand.

---

## FRIDAY is down
Symptoms: the health monitor alert fired / clients report no replies.

1. Check the process is serving:
   - Is something listening on :3737? (`lsof -iTCP:3737 -sTCP:LISTEN` or `ss -ltnp | grep 3737`) → should show a `node` PID.
   - `curl http://127.0.0.1:3737/api/health` → expect HTTP 200 with `{"status":"ok",...}`.
2. Check your process supervisor (systemd unit / launchd agent / pm2 process) is active, and tail its log.
3. Force a clean restart: restart the service through your supervisor, wait ~10s, re-check `/api/health`.
   - No supervisor configured? Run `npm run start` in the project directory for a foreground test run.
4. If the store looks corrupt (health `db` != ok): see **Database (JSON) restore**.
5. If unrecoverable within 30 min: send a holding message to active clients from the owner's OWN address.
   `[Owner: holding-message template]`

## Email pipeline down (FRIDAY up, no inbound processing)
1. `curl /api/health` → check `emailLoopLastRun`. If it's older than ~15 min, the `inbox-triage` job is stalled.
2. Likely cause: expired Google OAuth token. Re-auth: `[Owner: Settings → reconnect Google, or the token-refresh procedure]`.
3. Manual fallback: the owner monitors the `friday@` inbox directly until restored.

## An engine is down
Engine health: `curl /api/health` → `engines` block, or the 30-min `engine-auth-watch` job pages on lapse.
Re-login: `claude` → `/login` · `codex login` · (Hermes/Antigravity per their CLI).

| Engine | Roles it serves | Fallback |
|---|---|---|
| Claude | dev, architect, designer, qa, pm, support | hold + page — no adequate fallback (highest-consequence text) |
| Codex | devops, debug, seo | temporarily reassign role's `engine` to Claude in `agents.ts` |
| Hermes | research, sales, marketing | temporarily reassign to Claude |
| LM Studio | internal classification only (Tier-2 safety check, approval copy) | restart LM Studio server; degrades to fallback text |
| Antigravity | automation (browser) | hold — browser tasks, do not reroute |

## Database (JSON) restore
Last successful restore drill: `[Owner: DATE — REQUIRED; a backup never restored is a hope]`
1. Latest backup: the newest archive of `~/.agentic-os/friday/` produced by your backup job.
2. **Stop FRIDAY first** (stop the service through your supervisor) — the in-process memory index
   (`memory-embeddings.json`) will otherwise clobber restored files on write.
3. Restore: extract the chosen archive over `~/.agentic-os/friday/` (backups should exclude `workspaces/`,
   which is reproducible — leave it as-is).
4. Verify: spot-check row counts in `clients.json`, `tasks.json`, `approvals.json` and that yesterday's
   threads are present in `messages.jsonl`.
5. Restart FRIDAY; confirm `/api/health` is 200.

## Backup — how it works
Schedule a nightly job (cron, systemd timer, launchd, …) that archives the datastore (minus `workspaces/`)
to storage you trust, prunes copies older than `BACKUP_RETENTION_DAYS` (30), and pings a Healthchecks.io URL
on success (dead-man switch — a silent failure alerts on its own).
- `[Owner: create a Healthchecks.io check and set FRIDAY_BACKUP_HEALTHCHECK_URL to its ping URL]`

## Runaway / loop protection (reference)
- Auto-reply mail (out-of-office, lists, bounces) is detected and never answered (`isAutoGeneratedMail`).
- `[Phase 1] outbound rate caps` — per-thread/hour+day, per-contact/day, global-hour breaker.
- `[Phase 2] spend breaker` — per-task model-call/cost caps, per-day cost cap.
- Kill switches (env, default on): `FRIDAY_CLIENT_REVIEW`, `FRIDAY_APPROVAL_EMAIL`, `FRIDAY_TIER2_SAFETY_CHECK`.
- Self-edit gate: `SELF_EDIT_ENABLED` (default off) — FRIDAY's dispatched agents cannot edit her own source.

## Human handoff (a client asked for a person)
FRIDAY pages the owner, sends one warm "looping the owner in" reply, and goes quiet on that client's thread.
The owner takes over the thread directly. To hand it back: text FRIDAY **`resume <client first name>`** (or `resume all`).

## Deploying a change to FRIDAY herself (self-deploy)
FRIDAY's own source is version-controlled (git, local). Dispatched agents CANNOT edit it (`SELF_EDIT_ENABLED=false`, keep it off). To ship a change you (or Claude Code) made:
1. Commit the change (`git add -A && git commit`).
2. Rebuild (`npm run build`), restart the service, and confirm `/api/health` is 200. Keep the previous build around so you can roll back if the new one is unhealthy.
3. Rollback by hand if needed: `git checkout <prev>`, rebuild, restart.
- **Protected paths** (`src/lib/friday/protectedPaths.ts`): the approval/gate logic, client prompts, and secret-handling files. If an approval-gated agent self-deploy pipeline is ever enabled, changes to these require an explicit owner `protected_change` sign-off (`guardSelfDeploy`).
- **Eval harness:** `curl http://127.0.0.1:3737/api/friday/eval` → 200 if the deterministic safety classifiers (review accept/changes, approval approve/reject, auto-reply detection) still pass their golden cases; 500 lists regressions. Run it after any prompt/classifier edit.

## Rotate a leaked token/secret
1. Revoke at the provider: `[Owner: Netlify / Supabase / Google / Twilio / engine consoles]`.
2. Update `.env.local` in the project directory (git-ignored) and restart FRIDAY.
3. Audit the exposure window in `logs.jsonl` (and, once built, `model_calls`).

## OS agent settings (OS Settings → AI Agents)
FRIDAY reads her effective config from the OS edge function `agent-settings-get` (her OS JWT, `{ "include_subagents": true }`)
— `src/lib/friday/agentSettings.ts`. Keys: `friday` for her, `friday.<id>` for department subagents (builder, qa-e2e, …) and
dispatch specialists (architect, dev, qa, …). **NULL in the OS = keep the built-in.** Cached ~60s (scheduler job
`os-agent-settings` keeps it warm), 15s fetch timeout, last good snapshot kept in memory and in
`<data dir>/agent-settings.last-good.json`; never fetched + OS down → built-ins. FRIDAY never waits on the OS: chat/SMS turns wait ≤3s
for a cold fetch, then go on with last-good/defaults.

| OS setting | Where FRIDAY applies it |
|---|---|
| `status` paused/disabled | Router (`runIntent`) and planner (`orchestrate`) reply with a refusal; `dispatchTask` returns the reason; `executeRun` refuses before the engine (task → blocked, owner notified once/day); scheduled work is held (`scheduledBudgetBlock`). A paused subagent/specialist refuses only its own work. |
| `model.effective` / `fallback` | Intent router and `run_subagent` (`routerModel.ts`): `anthropic` → API with that model (needs `ANTHROPIC_API_KEY`), `google` → Gemini (needs `GEMINI_API_KEY`/`GOOGLE_AI_API_KEY`), anything else skipped. Error → next candidate → built-in (`claude-sonnet-5` API, else the CLI). Skips/failures log `intent.router.settings.model_*`. Only explicit (agent/parent) choices are used; org defaults need `FRIDAY_AGENT_SETTINGS_ORG_DEFAULTS=on`. **CLI engines (codex, claude CLI) keep their engine and model** — specialists honour status and limits only. |
| `limits.daily_budget_usd` | Narrows `DAY_MAX_COST_USD` (auto paths). A specialist row also caps that role's own spend per day. |
| `limits.max_calls_per_day` | New daily model-call ceiling on the auto paths (`withinSpendBudget`); per specialist on its own calls. |
| `limits.max_turns` / `max_tokens` | Router turns (built-in 6) / output tokens (1200 Anthropic, `GEMINI_MAX_OUTPUT_TOKENS` 8192 Gemini). Lower only. |
| `limits.rate_limit_per_minute` | Router model calls per agent key; the call over the limit fails the turn honestly. |
| `require_approval` | Router: irreversible tools always queue (the authority model may not waive them). Not applied to task dispatch. |
| `tools.allowed` / `denied` | Router catalog and each department subagent; the OS MCP allow-list for dispatched `claude -p` runs (`osCliMcpAllow`). Code list ∩ allowed − denied, never widens; `allowed` binds a catalog only when it names a tool in it. The native OS client (backend syncs) is not filtered. |
| `voice` | ElevenLabs phone/web voice id + stability/similarity/style (`channels.ts`) over `ELEVENLABS_VOICE_ID`/env. |
| `prompts` | Persona override append/replace + active templates on FRIDAY's soul (router) and on a subagent's soul (`run_subagent`). The operational/tool-honesty prompt is never replaced. |
| `knowledge` | Not applied yet (FRIDAY has no OS knowledge-collection read path). |

Usage: scheduler job `os-usage-report` (5 min) pushes new `modelCalls` rows to the OS MCP tool `agent_usage_report`
(`osUsageReport.ts`, cursor `<data dir>/os-usage-cursor.json`, first push backfills `FRIDAY_OS_USAGE_BACKFILL_DAYS`=7). It is
**inert until `agent_usage_report` is added to `FRIDAY_OS_TOOLS`** in agent-core `src/osmcp/allowlists.ts` (logs
`os.usage_report_not_allowlisted` once).

## Client documents (proposals / plans / strategy docs)
Upload on the client card (📄 button — any client status, past included) or drop files in the client's
Drive **Documents** folder (pulled by the daily `client-docs-drive-sync` job or the panel's Drive button).
Caps: 25MB/file, pdf/docx/txt/md/csv only, extraction capped at 60k chars. Every upload mirrors to
Drive, chunks into FRIDAY's memory (kind `doc`, client-scoped — feeds email/SMS/meeting-prep recall),
and distills a category-lensed brief that agent runs receive as an authoritative context block.
Recategorizing a doc regenerates its brief under the new lens (one LLM call). Deleting a doc removes
the record, the on-disk file, its memory chunks, and trashes the Drive copies. `reprocess` heals a
half-processed doc (re-extract → re-index → re-brief). Doc content is REFERENCE material: agents may
use it for accuracy, but pricing/dates/commitments still route through the normal approval gates.

Owner texts: `resume <client>` (take a client off manual handoff) · `resume sends` (clear the outbound breaker pause) · `sweep planning` (delete planning tasks untouched >7d — snapshots `tasks.json` to `_board-sweeps/<stamp>/` first).

## Client-comms & board invariants (the "are we organized?" checklist)
Everything below is ENFORCED in code and LOCKED by a golden case in `GET /api/friday/eval` (500 = a
guarantee regressed — do not deploy). The shared principle: **nothing is created, promised, or
escalated without first checking what already exists** (open tasks, recent completions, recent
commits, pending approvals).
1. **12h reply SLA** — FRIDAY answers a client only if the owner hasn't within `FRIDAY_REPLY_DELAY_HOURS`; held mail is retried, never lost.
2. **Clock restart** — the newest client message owns the clock; older siblings are superseded (one reply per conversation); the owner replying in-thread stands FRIDAY down.
3. **Project-only replies** — non-work mail is indexed + left for the owner (`email.unrelated_skipped`).
4. **Commit-aware replies** — last ~10 repo commits ride the reply prompt; shipped work is confirmed DONE, never re-promised.
5. **Duplicate-ask defense** (`dedup.ts`) — every extracted request is title-matched against the project's tasks before creation: dup-of-open appends a note ("already tracked"), dup-of-recent-done replies "already done", ambiguous creates WITH a "possible duplicate" flag. Never an LLM call.
6. **State-checked approvals** — every task approval carries `⚠ State check: …` (similar open/done tasks + matching commits) or `State check: clean.`, and a pending approval per task is unique (`approval.duplicate_suppressed`).
7. **Board hygiene** — daily job merges near-certain (≥0.85) same-project planning twins into the oldest card and digests the stale count; deletion of non-duplicates happens ONLY via the owner's `sweep planning` text, backup-first.
8. **Client-experience layer (2026-07-19)** — welcome/delivered/meeting-offer emails ALL ride approve-to-send (or explicit env + authority for auto); templated sends carry the branded shell with the plain part authoritative; client attachments are captured store-only; feedback is asked sparingly and parsed deterministically; a meeting is only ever booked from an unambiguous slot pick after a fresh free/busy check. Each core is eval-locked.
